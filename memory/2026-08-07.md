**产出**(提交 43d4e78,工作树干净):
- 解决方案 9 项目:`NControl.slnx`,src 下 Core / Infrastructure / Modules(Optimization、Applications、Cleanup、Repair、Tools)×5 / Presentation / App,外加 tools/NControl.SmokeTest。
- 技术基线:net10.0-windows WPF + MVVM(CommunityToolkit.Mvvm 8.4.0)+ Microsoft.Extensions.Hosting/DI/Logging + Microsoft.Data.Sqlite 10(SQLitePCLRaw 升 2.1.12 修复 NU1903 高危漏洞)。
- 功能目录 70 项、预设 4 个(轻度 8 / 推荐 18 / 深度 / 应用清理),高风险(advanced.*)不进任何预设。
- 执行中心:PowerShell 与 cmd 双执行提供程序、UAC 提权(输出走临时文件)、逐项进度/日志/取消、SQLite 任务记录(%LocalAppData%\NControl\ncontrol.db)。
- 页面:首页、一键优化、系统设置(分类芯片+高级区)、应用管理(真实 Get-AppxPackage 扫描)、清理维护、系统修复、实用工具(即时工具)、任务记录、设置、关于(来源台账)。
- 冒烟测试 28 项全 PASS(目录完整性/预设引用/无高风险/执行成功+失败路径/SQLite 持久化/搜索)。
- 启动验证:窗口真实渲染(句柄非零 + 像素扫描主色/背景)。

**关键坑**:
1. MainViewModel 构造期间经 `IServiceProvider.GetService` 解析 HomeViewModel,而 HomeViewModel 又依赖 MainViewModel → 单例构造期循环依赖,启动死锁(进程存活但窗口不可见)。修复:引入 `NavigationService`(Main 构造完成后回填),页面 VM 全部改依赖它。
2. PowerShell 5.1 的 Add-Type 不支持 C# 字符串插值。
3. WPF 无 CharacterSpacing 属性;XAML 中 Text 属性与元素体不能同时设置。
4. .NET 10 SDK 默认生成 .slnx 而非 .sln。
