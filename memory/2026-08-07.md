### 第八轮 B:防火墙恢复 bug 修复(07:00-07:11,提交 5660b27 前段)

用户实测反馈:关闭防火墙的恢复功能没用,恢复后仍出现"安全原因有些设置由你的组织决定"。

**根因(两个叠加)**:
1. RestoreCommandBuilder 对防火墙自动生成的恢复命令自相矛盾:`Set-NetFirewallProfile -Enabled True` 启用后,紧接着 `Remove-ItemProperty` 把本地 `EnableFirewall` 值删掉 → 配置变"未配置"。
2. 组策略残留:`HKLM:\SOFTWARE\Policies\Microsoft\WindowsFirewall\{DomainProfile,PrivateProfile,PublicProfile}\EnableFirewall=0` + `DisableNotifications=1` 未清理 → 安全中心判定"由你的组织管理",且组策略优先级压过本地配置。

**修复**:恢复命令 = `Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled True` + **清理 Policies 组策略残留值** + 若策略键空则删键;不再删除本地 EnableFirewall(改为写回 1)。真机实测闭环:关闭→False,恢复→True,策略键清除,本地值=1 ✅。冒烟测试新增 3 条防火墙恢复断言防回归(157 PASS)。

### 第八轮 D:全量真机测试工具 + provider 修复(07:20-07:46,进行中)

**发现并修复两个 provider 真实 bug**(影响 App 管理员模式真实执行):
1. **相对路径 bug**:PowerShellExecutionProvider 用 `FileName = "powershell.exe"` 相对名,提权后进程 PATH 被重置不含 System32\WindowsPowerShell\v1.0 → "系统找不到指定的文件"。修复:`PowerShellPath = Path.Combine(Environment.SystemDirectory, "WindowsPowerShell", "v1.0", "powershell.exe")`(RunDirectAsync 和 RunElevatedAsync 两处)。CommandExecutionProvider 的 cmd.exe 同样改绝对路径(风险较低但一致)。
2. **New-Item -Force 建键 bug**:provider 自动注入 `New-Item -Path '...' -Force` 对**已存在且有子键**的注册表键报"无法删除子项目录树"(如 HKLM\...\Control、HKCU\...\Explorer\Advanced)。修复:`if (-not (Test-Path '...')) { New-Item ... }` 才建键。

**测试中发现的其他问题**(未完全解决,挂起中):
- HomeGroupProvider(hpet 服务)本机不存在 → 服务类项需标记 SKIP(环境问题非功能问题)。
- Remove-ItemProperty -ErrorAction SilentlyContinue 删不存在的值 → $? = false → Exit 1 误报(功能实际 OK,是 provider 判定问题)。
- 隐藏小组件按钮(TaskbarDa):HKCU\...\Explorer\Advanced 键 ACL 特殊(Owner=SYSTEM + RESTRICTED ReadKey),Set-ItemProperty 报"未经授权"——第七轮已如实报失败,本轮复现;待确认是否真问题。
- 卓越性能电源计划:powercfg 在管理员 PATH 里找不到(又是 PATH 问题,powercfg 在 System32)→ 需同样用绝对路径或经 cmd.exe。
- 测试工具以管理员运行的方式:exec shell 非管理员,`Start-Process -Verb RunAs` 不可靠(UAC 弹窗被环境拒绝);可靠方式 = 先启动管理员 powershell(ConsentPromptBehaviorAdmin=0 自动批准),再在其中启动 exe(继承管理员令牌)。

**环境/工具经验**:
